# 后端生成质量优化卖点筛选

本文用于复赛方案、答辩讲稿和后续功能规划。目标不是把所有优化点都堆进主叙事，而是筛出最适合作为比赛卖点的几个核心方向；未入选的想法保留在备选池，后续可按时间和展示需要补充。

## 筛选原则

复赛阶段更看重“系统设计是否完整、能力链路是否高级、展示是否容易理解”。因此主卖点优先选择满足以下条件的方案：

- 能和当前后端 `文档解析 -> 多 Agent 生成 -> RAG 引用 -> AgentResult` 主链路自然衔接。
- 能用流程图、诊断卡片、指标表等方式直观看到。
- 不完全依赖大模型输出稳定性，即使真实效果波动，也能保留清晰的工程叙事。
- 能体现学习助手特色，而不是泛泛的“调用大模型总结”。

## 本次确认的非多 Agent 主卖点

除多 Agent 方向外，当前更适合作为复赛主叙事的三个卖点是：

1. `Learning Asset Pipeline`：学习资料知识资产化。
2. `Generation Observability Dashboard`：生成质量可观测。
3. `Mobile Learning Loop`：移动端学习闭环。

这三个方向和现有项目完成度贴合度更高。它们不要求额外证明“大模型一定输出得更好”，而是强调系统已经把学习资料变成结构化资产、把生成过程变成可观察链路、把学习流程放进移动端闭环。相比纯算法卖点，它们更适合复赛答辩，因为评委可以直接从页面、接口和文档中看到。

推荐总表述：

> 智序知识助手将学习资料转化为结构化知识资产，通过生成质量诊断让 AI 输出可观察、可追踪，并在移动端完成资料输入、笔记理解、引用核验、导图梳理和复习反馈的一体化学习闭环。

### 卖点 A：Learning Asset Pipeline

中文名：学习资料知识资产化。

核心表达：

> 系统不是一次性总结文档，而是把学习资料沉淀为可管理、可检索、可追溯、可复习的知识资产。

当前项目已经具备的基础：

- 后端统一输出 `AgentResult`，包含 `topic`、`summary`、`notes`、`sources`、`citations`、`mindMap`、`review`。
- 文本和文件输入都会进入统一解析、分块、生成、引用和持久化流程。
- 每次生成会保存 `result.json` 和 `chunks.json`，支持按 `resultId` 刷新、RAG 查询和继续问答。
- 前端有首页最近结果、笔记详情、引用浮层、思维导图、复习评估等页面，已经能消费同一份结构化结果。

当前不足：

- “知识资产”还主要停留在单个 `AgentResult`，缺少面向多个资料的资产库视图。
- 笔记、来源、导图、复习题之间虽然有关联，但前端没有明确展示“这是一份知识资产包”。
- 缺少资产元信息，例如资料类型、生成时间、学习模式、覆盖章节、复习状态、最近访问时间。
- 目前本地持久化偏 demo，后端运行目录和前端本地存储还没有统一的资产索引。

建议优化：

- 增加 `assetMeta` 或在 `_meta` 中标准化保存：资料类型、文件名、生成时间、chunk 数、学习模式、来源页数、资产版本。
- 在首页或笔记库增加“知识资产卡片”：显示笔记数、引用数、导图节点数、题目数、最近复习时间。
- 把 `notes -> sources -> review -> mindMap` 的关系包装成“知识资产包”文案，而不是分散功能入口。
- 后端增加轻量资产索引文件或接口，至少能列出最近生成的结果，支撑“资料库”叙事。

建议展示句：

> 每次上传资料后，系统都会生成一份 Learning Asset，里面同时包含结构化笔记、证据片段、概念导图和复习任务，而不是只返回一段总结文本。

### 卖点 B：Generation Observability Dashboard

中文名：生成质量可观测。

核心表达：

> 系统不仅生成结果，还记录生成链路、模型状态、引用质量和契约校验结果，让 AI 输出可以被诊断和评估。

当前项目已经具备的基础：

- `agentStages` 已经记录 M1-M7 阶段，可展示解析、生成、引用、复习、问答链路。
- `_meta.modelLog` 和 `modelLogs` 中有 provider、model、taskType、latency、status、fallbackUsed 等模型调用信息。
- `citationDiagnostics` 已经包含引用覆盖率、引用有效率、quote 命中率、平均置信度、低支持率、grounding 性能等指标。
- 前端结果页已有“后端诊断”卡片，展示 Pipeline、Provider、Model、Status、引用覆盖、Quote 命中，并能调用契约校验。
- 后端有 `evaluation.py`，可以计算启发式质量分和对比报告，说明项目已经有评测雏形。

当前不足：

- 质量指标分散在 `_meta`、`citationDiagnostics`、`validate` 返回和 evaluation 脚本里，没有形成统一的 `qualityDiagnostics`。
- 前端只展示少量指标，不能一眼看出生成质量总览。
- 缺少面向答辩的可视化评分，例如总分、可信度、结构完整度、复习覆盖度。
- 指标主要偏引用质量，对“学习质量”“结构质量”“移动端展示质量”的评估还不够。

建议优化：

- 增加统一的 `qualityDiagnostics` 字段或前端派生指标，包含 `overallScore`、`assetCompleteness`、`citationScore`、`reviewScore`、`mindMapScore`、`warnings`。
- 在结果页新增“生成质量诊断卡片”，用 4 个小指标展示：资料覆盖、引用可信、结构完整、复习可用。
- 把 `validateAgentResult` 的结果和 `citationDiagnostics` 合并展示，减少用户理解成本。
- 给每次生成输出一个“质量摘要文案”，例如“本次生成引用覆盖率 100%，导图节点 11 个，复习题 10 道，适合进入复习环节”。

建议展示句：

> 我们没有把 AI 输出当成黑盒，而是为每次生成建立可观测指标：它用了哪个模型、经历哪些阶段、引用是否有效、结构是否完整、是否适合复习。

### 卖点 C：Mobile Learning Loop

中文名：移动端学习闭环。

核心表达：

> 用户可以在手机端完成从资料输入到笔记理解、引用核验、导图梳理、复习评估和继续问答的一整条学习链路。

当前项目已经具备的基础：

- 已有 Android WebView APK，可在模拟器上安装运行，并通过 `http://10.0.2.2:8000` 连接电脑后端。
- 前端移动端页面完整覆盖：首页、AI 输入、生成结果、笔记、笔记详情、思维导图、复习评估、个人页后端配置。
- APK 支持本地 assets 加载，运行时配置后端地址，适合校园网、无公网或现场演示环境。
- 复习页已经能保存本地复习进度，笔记页支持复习模式和本地编辑快照。
- 结果页支持继续问答、RAG 检索、后端刷新和契约校验，已经有闭环雏形。

当前不足：

- “闭环”在页面上还不够显性，用户看到的是多个功能页，不一定理解为一条学习流程。
- 首页学习路径只有三步，未完整覆盖“输入 -> 生成 -> 引用 -> 导图 -> 复习 -> 反馈/问答”。
- 复习反馈偏本地记录，后端没有基于答题表现更新学习状态。
- 缺少一个演示用的闭环进度条或完成状态，难以在答辩时快速展示“链路跑完了”。

建议优化：

- 首页或结果页增加“学习闭环进度”：资料输入、AI 笔记、引用核验、导图理解、复习评估、继续问答。
- 在结果页突出 4 个入口：看笔记、查引用、看导图、做复习，形成明确行动路径。
- 复习完成后回写一个更醒目的学习反馈，例如“已完成本次复习，建议回看 2 个薄弱点”。
- 增加演示模式文案：即使网络受限，APK 仍可本地展示前端资源，并通过局域网访问电脑后端。

建议展示句：

> 我们把 AI 笔记能力放进移动端闭环：用户不是只拿到一份笔记，而是在手机上继续查证据、看导图、做复习、追问难点。

### 三个卖点的当前完成度对照

| 卖点 | 当前完成度 | 已有支撑 | 主要短板 | 优化优先级 |
|---|---:|---|---|---|
| Learning Asset Pipeline | 约 60% | `AgentResult`、持久化结果、笔记/引用/导图/复习页面 | 缺资产库视图、资产元信息和统一资产索引 | 高 |
| Generation Observability Dashboard | 约 55% | `agentStages`、`_meta.modelLog`、`citationDiagnostics`、校验接口、结果页诊断卡 | 指标分散，缺总览评分和前端可视化 | 最高 |
| Mobile Learning Loop | 约 70% | APK、移动端页面、后端连接配置、笔记/导图/复习/问答链路 | 闭环叙事不显性，复习反馈较弱 | 高 |

如果只做少量优化，建议优先顺序是：

1. 先强化 `Generation Observability Dashboard`，因为它最容易用现有指标包装成看得见的卡片。
2. 再强化 `Mobile Learning Loop`，把已有页面串成一条显性的学习路径。
3. 最后强化 `Learning Asset Pipeline`，补资产元信息和资料库视图，为长期产品化做铺垫。

### 移动端展示约束

这三个卖点虽然适合写进方案，但不能把所有信息都堆到同一个手机页面。移动端屏幕有限，功能过密会让界面显得拥挤，反而削弱演示体验。因此后续实现应遵守“主界面只给结论，详情页再给证据”的原则。

推荐信息架构：

```text
首页
  -> 只展示最近知识资产、学习闭环进度、下一步动作

结果页
  -> 只展示核心摘要、三个关键指标、主要行动入口
  -> 诊断详情折叠到二级卡片或调试面板

笔记详情页
  -> 专注阅读和引用回链
  -> 不塞入过多质量指标

导图页
  -> 专注概念关系和节点详情
  -> 不承载完整生成诊断

复习页
  -> 专注题目、掌握度、薄弱点和建议
  -> 只展示与复习相关的反馈
```

三条卖点在移动端的呈现方式建议：

| 卖点 | 移动端主界面展示 | 详情承载位置 | 避免的问题 |
|---|---|---|---|
| Learning Asset Pipeline | 一张“知识资产卡片”：主题、摘要、笔记数、引用数、题目数 | 笔记库或资产详情页 | 不要在首页塞完整笔记、导图、诊断 |
| Generation Observability Dashboard | 一个“质量摘要”：总分 + 2 到 3 个关键指标 | 结果页折叠诊断卡或调试页 | 不要把所有模型日志、引用指标直接铺开 |
| Mobile Learning Loop | 一个横向/纵向简短进度条：输入、笔记、导图、复习 | 首页或结果页顶部 | 不要把每一步的解释文案都展开 |

建议采用渐进式展开：

- 第一层：给用户一个明确结论，例如“本次资料已生成知识资产，引用覆盖 100%，建议开始复习”。
- 第二层：给行动按钮，例如“看笔记”“查引用”“看导图”“做复习”。
- 第三层：给诊断详情，例如模型日志、质量指标、引用审计、chunk 召回。

展示上要避免“比赛卖点直接等于页面功能堆叠”。更合适的做法是：答辩材料讲完整架构，手机端只保留最能帮助用户下一步操作的信息。这样既能讲出系统深度，也能保持移动端轻量、清爽、可用。

## 主卖点 1：多模态证据路由

推荐名称：`Multimodal Evidence Router`，中文可叫“多模态证据路由”或“图像价值判决 Agent”。

这是当前最值得突出的卖点。它解决的不是简单“支持图片识别”，而是“系统会判断哪些图片值得交给视觉模型，哪些图片只需要 OCR，哪些图片可以压缩成结构化摘要”。这个叙事比直接说“我们用了多模态模型”更高级，也更符合学习资料场景。

核心流程：

```text
PPT/PDF 输入
  -> 文档解析模块
      -> 文本/OCR 提取
      -> 图片区域提取
  -> 图像价值判决 Agent
      A档：OCR 足够，只传 OCR
      B档：可文字压缩，传结构化图像摘要
      C档：高视觉依赖，传原图 + OCR + 图像摘要
  -> 主笔记生成 Agent
  -> 结构化学习笔记
  -> 复核/补充 Agent
```

适合强调的价值：

- 解决 PPT/PDF 中流程图、结构图、表格截图、公式截图容易丢信息的问题。
- 避免所有图片无差别进入视觉模型，体现成本控制和上下文压缩能力。
- 能为每张关键图片生成“图像摘要”和“学习价值等级”，方便前端做诊断展示。
- 对比赛非常友好：可以展示图片被分为 A/B/C 档的过程，即使最终生成质量波动，流程本身也很有说服力。

建议展示形式：

- 后端诊断卡片：图片总数、A/B/C 档数量、高视觉依赖图片列表。
- 结果页提示：本次资料发现 3 张关键图，其中 1 张流程图已进入视觉理解链路。
- 文档架构图：把它放在文档解析和主笔记生成之间，作为智能路由层。

## 主卖点 2：学习目标路由

推荐名称：`Learning Objective Router`，中文可叫“学习目标判别 Agent”。

这个卖点用于把系统从“资料总结器”升级成“学习场景助手”。同一份资料，考试复习、课堂预习、论文阅读、汇报速览需要的输出结构并不一样。学习目标路由 Agent 可以先判断当前资料和用户意图，再选择不同的生成策略。

核心流程：

```text
输入资料
  -> 学习目标判别 Agent
      考试复习型
      课程预习型
      概念理解型
      论文阅读型
      汇报速览型
  -> 选择对应 Prompt 模板和输出重点
  -> 主笔记生成 Agent
```

适合强调的价值：

- 让输出从“统一模板”变成“面向学习目的的自适应生成”。
- 比赛答辩时容易解释：考前要重点和题，预习要概念和例子，论文阅读要问题、方法、贡献。
- 可以和前端设置联动，用户可选择学习模式，也可以由后端自动识别。
- 实现成本可控，先做轻量分类和 prompt 模板切换，也能形成完整卖点。

建议展示形式：

- AI 输入页显示“当前识别为：考试复习型/概念理解型”。
- 结果页显示“本次生成策略”：重点提炼、易错点、复习题、学习路径。
- 答辩讲稿中强调“不是一套 prompt 打天下，而是先判别学习任务，再生成内容”。

## 主卖点 3：可信引用审计

推荐名称：`Evidence Trace Auditor`，中文可叫“可信引用审计 Agent”或“证据链审计”。

当前后端已经有 RAG grounding 和 citation diagnostics，这是最接近已有能力的卖点。建议把它包装成“生成结果不是孤立文本，而是带证据链的结构化学习资产”。

核心流程：

```text
主笔记生成 Agent
  -> RAG Grounding
      重建 notes -> sources 引用
      提取 quote 和定位信息
      校验复习题引用
  -> 可信引用审计
      引用覆盖率
      引用有效率
      quote 命中率
      低置信引用告警
  -> AgentResult
```

适合强调的价值：

- 降低大模型幻觉风险，避免笔记内容没有来源支撑。
- 每条笔记、复习题都可以回链到原文片段。
- 可以用量化指标展示可信度，比如引用覆盖率、断链率、quote 命中率。
- 这是比赛评委容易认可的“可靠 AI”方向，不依赖模型输出有多华丽。

建议展示形式：

- 结果页“后端诊断”展示：引用覆盖率、引用有效率、quote 命中率。
- 笔记详情页点击引用编号，弹出原文片段。
- 方案材料中写成“可追溯、可审计、可解释的学习笔记生成”。

## 主卖点 4：教学质量复核

推荐名称：`Pedagogical Critic Agent`，中文可叫“教学质量复核 Agent”。

这个卖点用于补齐“生成后自我检查”的闭环。主生成 Agent 负责产出，复核 Agent 负责检查覆盖是否完整、引用是否可靠、复习题是否有效、导图是否遗漏核心概念。它可以不强依赖模型绝对稳定，因为即使只是输出诊断项和修复建议，也很适合比赛展示。

核心流程：

```text
AgentResult 草稿
  -> 教学质量复核 Agent
      覆盖度检查
      引用一致性检查
      导图完整性检查
      复习题有效性检查
  -> 修复/补充建议
  -> 最终 AgentResult
```

适合强调的价值：

- 让系统形成“生成 -> 评价 -> 修复”的质量闭环。
- 可以输出质量评分，让评委直观看到系统不是盲目生成。
- 能和现有 citation diagnostics、validate 接口自然结合。
- 后续可以逐步扩展为自动修复 Agent，但第一阶段先展示评分和建议即可。

建议展示形式：

```json
{
  "coverageScore": 86,
  "citationScore": 94,
  "structureScore": 82,
  "reviewScore": 78,
  "repairSuggestions": [
    "补充第 3 节核心概念",
    "为 2 条低置信笔记重新绑定引用",
    "增加 1 道易错点复习题"
  ]
}
```

页面上可以做成“质量诊断卡片”，展示总分、四个维度和修复建议。这个卡片很适合作为答辩截图。

## 推荐主叙事

建议把四个主卖点串成一句话：

> 智序知识助手不是简单调用大模型总结资料，而是构建了面向学习质量的多 Agent 流水线：先识别学习目标，再对文本、OCR 和图片证据进行智能路由，生成后通过可信引用审计和教学质量复核，产出可追溯、可复习、可诊断的结构化学习笔记。

推荐架构图：

```text
学习资料输入
  ↓
Learning Objective Router 学习目标路由
  ↓
Semantic Document Parser 文档解析
  ├── 文本/OCR
  ├── 表格/公式
  └── 图片区域
        ↓
Multimodal Evidence Router 多模态证据路由
  ↓
Main Note Generation Agent 主笔记生成
  ↓
Evidence Trace Auditor 可信引用审计
  ↓
Pedagogical Critic Agent 教学质量复核
  ↓
结构化 AgentResult
```

主卖点优先级建议：

1. `Multimodal Evidence Router`：最亮眼，最容易和普通总结工具拉开差距。
2. `Evidence Trace Auditor`：最贴合可信 AI 和引用回链，是已有能力的加强包装。
3. `Pedagogical Critic Agent`：最适合做可视化诊断卡片，展示完成度高。
4. `Learning Objective Router`：最能体现产品理解，适合放在方案开头。

如果开发时间有限，建议先做 2、4 的展示，因为它们最容易基于现有后端产物补指标；再做 1 的最小闭环；最后做 2-3 个学习目标模板。

## 备选方案池

以下方案不作为主卖点，但建议保留在后续扩展或答辩问答中。

### 文档结构理解 Agent

也可以叫 `Semantic Document Parser`。它强调标题层级、表格、公式、代码块、例子、定义、结论等结构识别。这个方向有价值，但和现有“文档解析与分块”比较接近，适合放在基础能力中，不建议抢主卖点位置。

### 知识点依赖图 Agent

也可以叫 `Concept Dependency Graph`。它把普通思维导图升级为前置知识、组成关系、对比关系、应用关系、证据关系等。这个方向适合增强导图，但如果主卖点太多，容易和“思维导图”展示混在一起，建议作为后续增强。

### Bloom 教育目标出题 Agent

也可以叫 `Bloom-Aware Review Generator`。它把复习题按记忆、理解、应用、分析等层级生成。这个卖点很教育学，但需要前端展示配合，否则容易停留在文档层。适合二期加到复习评估页。

### 个性化学习画像 Agent

也可以叫 `Knowledge State Estimator`。它基于答题结果推断已掌握、薄弱、易混概念，再推荐复习路径。这个方向很像完整学习闭环，但需要用户行为数据支撑。当前阶段可以作为未来规划，不宜作为主卖点。

### 输出风格控制 Agent

也可以叫 `Adaptive Note Style Agent`。它支持学霸笔记风、考研冲刺风、小白解释风、课堂讲义风等。展示效果直观，但技术含量看起来偏 prompt 包装，建议作为产品体验增强，不作为核心技术卖点。

### 缺失上下文诊断 Agent

也可以叫 `Context Sufficiency Analyzer`。它检查资料是否缺定义、缺图表解释、跨页断裂、指代不明。这个方向和你的图像价值判决很契合，但范围更宽。建议并入主卖点 1 或主卖点 4，不单独成为主卖点。

### 多候选生成与仲裁 Agent

也可以叫 `Multi-Candidate Synthesis Agent`。它生成多个候选版本，再由仲裁 Agent 合并优点。听起来高级，但成本较高，而且真实效果不稳定，容易拖慢演示。适合写入“高级扩展”，不建议复赛主做。

### 覆盖率评估 Agent

也可以叫 `Learning Coverage Evaluator`。它统计章节覆盖率、关键词覆盖率、导图覆盖率、复习题覆盖率。这个方向很好，但建议并入“教学质量复核 Agent”，作为其指标维度之一，而不是单独讲。

## 最小落地建议

如果后续要把主卖点逐步做出来，推荐按以下顺序：

1. 先把现有 citation diagnostics 包装成 `Evidence Trace Auditor` 指标卡。
2. 增加一个轻量 `qualityDiagnostics` 字段，承载教学质量复核评分和建议。
3. 为 PPT/PDF 解析结果补充图片区域清单，并先用规则生成 A/B/C 档，再逐步接入视觉模型。
4. 增加学习目标字段 `learningMode`，先支持用户选择，再做自动判别。

这样即使时间有限，也能形成一条完整的比赛叙事：有智能路由、有可信证据、有质量诊断、有学习目标适配。
